# HaTikvah Care: notes for future work

* Stack: React + Vite (`apps/web`), Express (`apps/api`), MongoDB (production) / JSON files (dev), Cloud Run. Plain JavaScript (ESM).
* Money is stored as integer **paise** (`price`), `null` = "price on request".
* Public API returns only live products; prices hidden when `settings.showPrices` is false. Admin mutations require the session cookie AND the `X-Requested-With: hc-admin` header (CSRF).
* Only `apps/api/src/store/*` may touch the database. Keep the file and Mongo stores behaviour-identical (`test/store.test.js` is the contract).
* Seeding runs only on an empty database (`src/seed.js`). Never overwrite live data from `data/catalog.json`.
* Secrets only via environment (`JWT_SECRET`, `MONGODB_URI`). The server refuses unsafe production config (`src/config.js`).
* Before pushing: `npm test` and `npm run build`.
* Business flow: enquiry → customer → quote (`/doc/quote/:token`, accepted online) → sales order → dispatch (challan) → GST invoice → payments. GST maths lives only in `src/lib/gst.js` (the web editor mirrors it for display; the server's totals are saved). Document numbers come from `store.nextSeq` per financial year.
* Permissions: `src/lib/permissions.js` (roles → modules); guard new admin routes with `requirePerm`.
* All outgoing messages go through `src/lib/notify.js` (outbox). WhatsApp format is decided at send time by `buildWhatsAppMessage`: free-form inside the customer's 24-hour window (last inbox message), else the kind's template (`WA_TEMPLATES`: quote / dispatch / invoice, env `WHATSAPP_TEMPLATE_*`), else the general `WHATSAPP_TEMPLATE`, else kept as "send by hand". Pass `template: { kind, params, button }` from automation for customer documents. Rules and scheduled jobs: `src/lib/automation.js`. Integrations are env-only and optional (docs/INTEGRATIONS.md).
* Buyer portal: `/account` (`apps/web/src/buyer/`) over `src/routes/buyer.js` (`/api/buyer/*`). Sign-in is the shop's WhatsApp code (`/api/shop/auth/request-code`, `/auth/verify-code`; cookie `hc_shop` for `BUYER_SESSION_DAYS` (30), sliding: re-issued when over a day old). Every buyer query filters on the signed-in `customerId`; others' records answer 404. Quote acceptance (doc link and portal) goes through `respondToQuote` in `src/lib/sales.js`.
* Online shop: `src/routes/shop.js` (WhatsApp OTP sign-in, checkout, my orders). Switches live in settings and are limited by which keys exist (`shopFlags` in `src/lib/notify.js`). Bulk tier pricing is `tierPrice` in `src/lib/sales.js` (the web `ProductCard.jsx` mirrors it). Paid online orders get their GST invoice from the Razorpay webhook, never at checkout.
* Packaging: products have `measure` (volume / weight / dimensions / count) and `packaging` (piece → inner pack → master carton) with `packPrices`; `src/lib/units.js` is the only place that expands them. Document lines keep the ordered unit (`uom`, `qty`, `rate`) plus `perUnit` (pieces per unit, fixed server-side in `priced()`); stock always moves in pieces (`pieces(line)`).
* Stock buckets: `stockBuckets()` in `src/lib/sales.js`: physical (ledger), reserved (open confirmed/packed orders without an invoice), available = physical − reserved; low stock and the website use available. Batches live on stock moves (`batch: { batchNumber, mfgDate, expDate }`), allocated FEFO by `batchLevels()`.
* Direct booking: `bookEnquiry` in `src/lib/sales.js` (route `POST /api/admin/enquiries/:id/book`, needs `enquiries` and `orders`, modal `admin/BookingModal.jsx`). Customer, confirmed order and enquiry commit together; the order is the stock reservation. Repeats return the same order; an open quote on the enquiry blocks it. The receipt is the `orderBooked` automation: no template kind of its own yet, so outside the window it uses the general `WHATSAPP_TEMPLATE`.
* Credit notes: `createCreditNote` in `src/lib/sales.js` (routes `/api/admin/credit-notes`, doc `/doc/creditnote/:token`, numbers `CN-YY-0001` per financial year). Lines reference invoice lines by index; HSN, GST and unit come from the invoice; quantity and value are capped by what is left. Returns/wrong items restock (in pieces, batch required for batch-tracked products); a `credit_notes` ledger row is posted; the invoice's `creditedAmount` lowers `balance()`, and `refundDue()` shows money owed back. Invoices with credit notes cannot be voided.
* Every payment posts a `ledger` row (cash / bank / razorpay) via `recordPayment`; deleting the payment deletes it. Counter billing: `src/routes/pos.js`.
* Couriers: all HTTP in `src/services/delivery_shadowfax.js` and `delivery_porter.js`, routes and both webhooks in `src/routes/logistics.js` (`COURIERS` map, `POST /api/admin/orders/:id/shipment`, modal and timeline in `admin/Logistics.jsx`). A pickup needs a dispatched order. The shipping label is `/doc/label/:token`, one page per package, barcode from JsBarcode (CODE128 of the AWB, else the challan number).
* Payment links and counter QR: `src/lib/payments.js`. `refreshPayLink` keeps one link per amount and moves replaced links to `payLinkHistory`, because they stay payable. A counter UPI QR belongs to an invoice that already exists (`POST /api/admin/pos/invoice` without a payment, then `/pos/invoices/:id/upi-qr`); `applyQrPayment` settles it from the `qr_code.credited` webhook or the `?sync=1` check, once per Razorpay payment id. Anything unrecognised goes to `holdForReconciliation`, never onto an invoice.
* WhatsApp inbound: `src/routes/whatsapp.js` (webhook, bot, inbox). Roles `admin` (= owner rights), `billing_executive`, `warehouse_manager`, `sales_representative` in `permissions.js`.
* `npm run seed-demo` fills a dev database with sample data for previews (refuses production).
* Known gaps: Shadowfax and Porter field names (and whether either honours the pickup slot) need confirming against the account's API doc; invoice "PDF" is the printable doc link (no server-side PDF); no debit notes or credit-note cancellation, no e-invoice/e-way bill, no direct Tally/Zoho sync; product images are the supplier's catalogue photos.
